# Community & Getting Help

Wherever you get stuck — setting up locally, understanding a piece of the codebase, or figuring out whether something is a bug — there's somewhere to ask. Here's what each channel is for.

## Slack

[**Join the OpenBoxes Slack**](http://slack-signup.openboxes.com/)

The fastest way to get an answer. Good for setup problems, quick questions about the codebase, and finding out whether someone is already working on something. If you're picking up your first issue and want a steer on which one, ask here.

## Community forums

[**community.openboxes.com**](https://community.openboxes.com/)

Longer-form discussion, implementation questions from people running OpenBoxes, and [release announcements](https://community.openboxes.com/c/announcements/12). Better than Slack when you want an answer that stays findable.

## GitHub

* [**Issues**](https://github.com/openboxes/openboxes/issues) — bug reports and tracked work. See [Report a Bug](../contribute-without-code/report-a-bug.md).
* [**Discussions**](https://github.com/openboxes/openboxes/discussions/categories/ideas) — feature ideas and open-ended proposals. See [Suggest a Feature](../contribute-without-code/suggest-a-feature.md).
* [**Pull requests**](https://github.com/openboxes/openboxes/pulls) — code review happens here.

## Email

For anything that doesn't fit the above — including requesting edit access to this guide in the GitBook editor — email [support@openboxes.com](mailto:support@openboxes.com).

## A note on where development happens

The bulk of feature development in the core repository is driven internally by Partners In Health (PIH), which is why you'll sometimes see pull requests referencing tickets from a PIH-only Jira board. We're working to move more of that conversation into public GitHub issues and discussions. If a pull request references a ticket you can't open, ask on Slack and someone will fill in the context.
